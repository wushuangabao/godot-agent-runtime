# 迁移到 0.2 输入契约

本文记录 0.2 开发周期内已经启用、但包版本将在 Task 9C 统一发布的安全输入变化。安全 guard 没有静默兼容期：旧调用会得到结构化错误和可执行的恢复建议，不会在未知文件、项目或活动场景上继续写入。

## 两项破坏性输入变化

### 1. 文件写入必须携带 guard（Task 2）

`godot_file_write` / `file-write` 不再接受无条件覆盖。创建文件传 `guard: { mode: "create" }`（CLI：`--create-only`）；更新文件先用 `godot_file_read` 取得 SHA-256，再传 `guard: { mode: "match", sha256 }`（CLI：`--expected-sha256 HASH`）。过渡期仍识别旧的 `expectedSha256` 字段，但不携带任何 guard 会失败为 `FILE_GUARD_REQUIRED`。

`godot_file_replace` / `file-replace` 还必须传 `expectedProjectFingerprint`（CLI：`--project-fingerprint HASH`）。指纹从 `godot_project_context.identity.projectFingerprint` 获取；项目身份变化时失败为 `PROJECT_IDENTITY_MISMATCH`。

### 2. 持久 Editor 修改必须绑定活动场景和历史（Task 4）

下列 MCP 工具新增必填 `expectedScenePath`；对应 CLI 命令新增 `--expected-scene RES_PATH`：

- `godot_editor_node_create`、`godot_editor_node_update`、`godot_editor_node_delete`、`godot_editor_node_move`
- `godot_editor_scene_instantiate`
- `godot_editor_instance_set_editable`
- `godot_editor_resource_create`、`godot_editor_resource_update`、`godot_editor_resource_save`
- `godot_editor_signal_connect`
- `godot_editor_scene_save`、`godot_editor_undo`、`godot_editor_redo`

对应 CLI 旧命令名保持不变：`editor-node-create/update/delete/move`、`editor-scene-instantiate`、`editor-instance-set-editable`、`editor-resource-create/update/save`、`editor-signal-connect`、`editor-save/undo/redo`。这些修改工具还可传 `expectedProjectFingerprint`（CLI：`--expected-project-fingerprint HASH`），Core 会在连接桥接层之前验证项目身份。

`godot_editor_scene_save`、`godot_editor_undo` 和 `godot_editor_redo` 还必须传 `expectedHistoryVersion`（CLI：`--expected-history-version N`）。undo/redo 可选传 `expectedActionName`（CLI：`--expected-action NAME`）加强校验，但动作名不能替代版本。

缺少场景 guard 返回 `EDITOR_SCENE_PATH_REQUIRED`；活动标签不同返回 `EDITOR_SCENE_MISMATCH`；缺少历史 guard 返回 `EDITOR_HISTORY_VERSION_REQUIRED`；原生 Godot history 已变化返回 `EDITOR_HISTORY_CONFLICT`。这些失败都发生在创建 Undo action、保存或撤销/重做之前。

### 3. 类型化 Editor 批处理（Task 5）

新增 `godot_editor_batch` / `editor-batch`。请求必须携带 `expectedProjectFingerprint`、`expectedScenePath`、1–32 个严格 tagged-union 操作和显式 `confirmDestructive`；CLI 对应 `--project-fingerprint`、`--scene`、`--operations JSON_ARRAY`、`--confirm-destructive true|false`。支持的操作只有 `node_create`、`node_update`、`node_move`、`node_delete`、`scene_instantiate`、`resource_create`、`resource_update`、`instance_set_editable`、`signal_connect`，未知操作或字段在进入桥接层前被拒绝；含删除时确认值必须为 `true`。

全部操作针对按顺序更新的逻辑场景索引预校验，通过后才注册为一个 `EditorUndoRedoManager` action。批处理没有 `save` 字段，成功只表示内存场景已应用、dirty 且可整体撤销；磁盘持久化仍需随后携带最新 `historyVersion` 单独调用 guarded save。保存失败不会把已应用批次改写成失败或自动撤销。

## 新调用顺序

1. 调用 `godot_project_context`，保存 `identity.projectFingerprint`。
2. 调用 `godot_editor_status` / `editor-status`，读取精确的 `scene` 和 `historyVersion`。
3. 如需切换标签，调用 `godot_editor_scene_open` / `editor-scene-open`，传项目指纹和项目内 `.tscn`；以结果的 `scene`、`historyVersion` 作为新 guard。
4. 每次持久 mutation 传当前 `expectedScenePath`；其成功 receipt 会返回新的 `historyVersion`。
5. save/undo/redo 传最新 `expectedScenePath` 和 `expectedHistoryVersion`，并继续使用响应中的 `historyVersion`。

旧调用示例（拒绝执行）：

```json
{
  "name": "godot_editor_node_create",
  "arguments": {
    "projectPath": "C:/game",
    "runId": "...",
    "parentPath": "/root/Main",
    "type": "Label",
    "name": "Unsafe"
  }
}
```

新调用示例：

```json
{
  "name": "godot_editor_node_create",
  "arguments": {
    "projectPath": "C:/game",
    "runId": "...",
    "expectedProjectFingerprint": "<godot_project_context 返回的 SHA-256>",
    "expectedScenePath": "res://main.tscn",
    "parentPath": "/root/Main",
    "type": "Label",
    "name": "Guarded"
  }
}
```

## 桥接版本

Editor 与 Runtime 现在独立协商：`EDITOR_PROTOCOL_VERSION = "0.7.0"`，`RUNTIME_PROTOCOL_VERSION = "0.4.0"`。两类 Bridge 都新增 `screenshot_receipt` capability；截图输入可选传 `expectedScenePath`，并把捕获前后的真实活动场景绑定到回执。旧 Addon 会以对应的 `EDITOR_PROTOCOL_VERSION_MISMATCH` / `RUNTIME_PROTOCOL_VERSION_MISMATCH` 快速失败并提示重装。`PROTOCOL_VERSION` 暂时是指向 Runtime 版本的 deprecated alias，doctor 同时返回 `protocolVersion` 和 `protocolVersions: { editor, runtime }`；alias 的移除安排在 Task 9C 收口。

截图的旧字段保持不变，新增严格的 `evidence`：Editor 截图标记为 `editor_viewport` 且 `provesRuntime:false`，Runtime 截图标记为 `runtime_frame` 且 `provesRuntime:true`；两者都明确 `provesInteraction:false`。如果捕获前场景与 `expectedScenePath` 不同，返回 `EVIDENCE_SCENE_MISMATCH`；如果等待/写入期间活动场景改变，Bridge 删除 PNG 并返回 `EVIDENCE_SCENE_CHANGED_DURING_CAPTURE`。

0.6.0 新增 `godot_editor_project_setting_get/set`、`godot_editor_input_action_upsert` 和 `godot_editor_resource_inspect`。持久配置写入必须同时传 `expectedProjectFingerprint` 与最新 `expectedProjectFileSha256`；成功 receipt 返回 before/after SHA-256 且 `undoable:false`。调用方若直接修改过 `project.godot`，必须重启受管 Editor 让 ProjectSettings cache 重新加载，不能用新 SHA 请求旧 Editor 覆盖磁盘。
